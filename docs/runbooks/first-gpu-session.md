# 첫 GPU 검증: 함께 진행하는 순서

상태: 유료 자원 생성 전 준비. 실제 GPU 성공 기록이 아니다.

2026-09-17 콘솔 조회에서는 로그인이 완료되어 있고 표시 잔액은 $0.00이었다. `Available` 목록에 L4 24GB $0.49/시간, RTX 3090 24GB $0.50/시간, RTX A6000 48GB $0.53/시간이 보였다. 이전 후보 A5000은 해당 목록에서 보이지 않았다. 장비를 선택하거나 생성한 결과가 아니며, 지역·등급·Full SSH 조건과 최종 합계는 미확정이다. 현재 기본 템플릿은 PyTorch이므로 그대로 생성하지 않는다.

## 1. 지금 사용자가 할 일

[Runpod 콘솔](https://console.runpod.io/)에 가입하고 로그인한다. 이 단계에서는 충전하거나 Pod 생성 버튼을 누르지 않는다. 로그인한 뒤 알려 주면 장비 선택 화면에서 실제 가격과 사용 가능한 GPU를 함께 확인한다. 비밀번호·카드 번호·인증코드·개인 SSH 키는 대화나 저장소에 남기지 않는다.

## 2. 대여 전에 준비할 것

AI 서버를 잠긴 작업실처럼 운영한다. 외부에 여는 문은 SSH 접속 하나이고, AI 요청은 그 연결 안으로 전달한다. Runpod에서는 공인 IP와 Full SSH가 가능한 장비가 필요하다. Basic SSH만 가능한 장비를 포트 전달이 된다고 가정해 선택하지 않는다.

- 배포 이미지의 SSH 서버와 종료 동작을 GPU 없이 먼저 검사한다.
- 이미지 전체 빌드 및 레지스트리 업로드 후 실제 digest를 기록한다. 업로드 위치와 공개 범위는 먼저 정한다. 소스 저장소 전체나 키를 이미지에 넣지 않는다.
- 전용 SSH 키를 로컬에서 만들고 **공개키만** 계정 또는 Pod 설정에 등록한다. 기존 키를 덮어쓰지 않는다.
- GPU는 24GB 메모리 장비 한 대를 후보로 비교한다. 모델은 기존 Qwen 4B, BF16, 문맥 4096, 동시 시퀀스 1개로 시작한다. 구체적 장비는 가용성과 실제 견적 확인 후 확정한다.
- TCP 공개 포트는 SSH의 22만 설정한다. 8000 HTTP/TCP 공개 및 Jupyter는 추가하지 않는다.
- 컨테이너 디스크는 이미지와 모델 다운로드 여유를 확인해 정한다. 첫 시험에서 장기 보관용 네트워크 볼륨을 자동으로 추가하지 않는다.

전체 vLLM 이미지는 크다. GPU 없이 접속·종료 검사가 통과해도 NVIDIA 드라이버 호환성이나 실제 모델 기동까지 검증된 것은 아니다. 원격 GPU 대여는 이미지 준비와 견적 승인 이후에만 진행한다.

## 3. 비용 승인 화면

실제 선택 화면을 확인하고 아래 항목을 채운 뒤 사용자 승인을 받는다. 이전 문서의 공개 단가는 참고 기록이며 오늘의 견적이 아니다.

| 확인할 항목 | 승인 전에 채울 값 |
|---|---|
| GPU / 개수 / 메모리 / 지역 / 클라우드 등급 | 미확정 |
| GPU 시간당 단가 | 미확정 |
| 디스크 종류·크기와 별도 저장소 요금 | 미확정 |
| 공인 IP·세금·결제 수수료 | 미확정 |
| 최초 충전액 / 실제 예상 소비액 | 각각 확인 |
| 첫 실행 시간 상한과 종료 시각 | 생성 직전 확정 |
| 이번 실행 비용 상한 / 누적 예산 잔액 | 사용자 승인 전 확정 |

프로젝트 전체 상한은 합의한 10만 원이다. 처음 설명한 2~3시간은 작업 시간 확보 권고이며 자동 과금 승인이나 종료 예약이 아니다. 준비·다운로드에도 과금 시간이 흐르므로 실제 첫 대여 시간과 비용 상한은 별도로 정한다. 자동 충전은 사용하지 않는다. Runpod 크레딧은 환불되지 않으므로 충전액과 실제 소모액을 구분한다.

## 4. 접속 후 검증 순서

1. 관리 콘솔에서 서버 SSH 지문을 확인한 뒤 터널을 연결한다.
2. GPU·드라이버·이미지 digest·모델 revision을 기록한다.
3. 한국어 첫 답변과 스트리밍을 검사한다.
4. 생성 중인 요청을 실제로 관측한 뒤 연결을 끊고, vLLM 활성 요청 수가 기준선으로 돌아오는지 확인한다. 클라이언트 연결 종료만으로 GPU 취소 성공이라고 쓰지 않는다.
5. 터널 중단 시 오류와 재연결 후 정상 응답을 확인한다.
6. 남은 시간 내에 CPU 임베딩·API와 연결해 가상 회사 PDF의 질문·출처를 확인한다. 이를 못 마치면 미완료로 남긴다.
7. 비밀값을 제외한 결과를 로컬 문서에 저장하고 정해진 시간에 자원을 종료한다.

실제 명령은 [모델 서버 기동 절차](deployment.md), 결과는 [환경 기록](../experiments/environment.md), 비용은 [비용 원장](../experiments/cost-ledger.md)에 남긴다. 본격적인 동시 요청 성능 비교는 관측 기능 준비 후 별도로 진행한다.

첫 RAG 연결 확인에는 저장소의 `tests/fixtures/pdfs/authored_korean.pdf`를 사용한다. 직접 작성한 “연차 휴가는 사전에 신청합니다.” 한 문장이 들어 있다. “연차 휴가는 언제 신청하나요?”를 질문하고 해당 PDF가 출처로 표시되는지 확인한다. 이는 한국어 PDF 연결 점검이며 긴 문서의 검색 품질 평가를 대신하지 않는다.

## 5. 종료 확인

SSH 창이나 vLLM 프로세스를 닫는 것만으로 과금이 끝나지 않는다. 이번 실험에서 만든 Pod를 식별하고 필요한 기록을 보관한 후 종료·제거 상태를 확인한다. 남겨 둔 볼륨에도 비용이 발생할 수 있으므로 저장소와 Billing 화면을 따로 확인한다. 다른 작업의 자원은 건드리지 않는다.
