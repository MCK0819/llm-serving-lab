# 인증과 조직 구분 검증

2026-09-11, 구현 계획 Task 4. 실제 GPU는 사용하지 않았다.

## 쉽게 설명하면

사용자마다 출입증(API Key)을 발급한다. 서버는 출입증을 확인해 사용자와 소속 회사를 찾는다. 요청에 다른 회사 이름표를 붙여도 소속을 바꿀 수 없다. 출입증을 폐기하면 다음 요청부터 사용할 수 없다.

출입증 원문은 발급할 때 한 번만 보여주고 DB에는 검증용 해시만 저장한다. 관리 명령은 서버 운영자가 실행하며 공개 회원가입 기능은 없다.

## 구현한 범위와 선택 이유

- PostgreSQL에 조직·사용자·키 테이블을 만들고 Alembic으로 스키마 변경을 관리한다. 키는 사용자를 참조하고 사용자가 조직을 참조하므로 요청의 임의 조직 ID를 사용할 필요가 없다.
- 키는 UUID 식별자와 `secrets.token_urlsafe(32)`로 생성한 비밀값으로 구성한다. 비밀값은 충분한 난수를 사용하므로 SHA-256 검증용 해시와 상수 시간 비교를 사용한다. 사람이 정하는 비밀번호에 같은 저장 방법을 적용하는 설계는 아니다.
- `router → 인증 service → 구체 repository → PostgreSQL` 순서로 호출한다. 범용 Repository 기반 클래스는 만들지 않았다.
- 요청 인증에 사용한 DB session은 조회 직후 닫는다. 답변을 천천히 전송하는 동안 트랜잭션을 유지하지 않는다. 앱마다 별도 연결 풀과 하나의 Admission을 조립한다. 엔진 생성은 지연 연결이며 lifespan 종료 시 풀을 닫는다.
- 잘못된 키는 401, 인증 저장소 연결 문제는 안전한 503으로 응답한다. 키·DB 설정을 오류 응답에 그대로 넣지 않는다.
- 질문은 인증 후 실제 수신 바이트 16 KiB를 제한하고 JSON으로 해석한다. 빈 질문·임의 조직/사용자/모델 필드는 거부한다. 이 제한은 질문 경로를 만들 때 함께 적용했다.
- `POST /questions`는 인증 경로까지 연결했다. 기본 실행에서는 유효한 키여도 `503 rag_unavailable`을 반환한다. Task 9의 실제 문서 검색이 연결되기 전까지 근거 없는 일반 채팅을 열지 않는다. 성공 스트림은 테스트에서 명시적으로 주입한 준비 함수로 검증한다.

## 검증 결과

| 환경 | 결과 |
|---|---|
| Windows, Python 3.14.7 | 단위 테스트 89개 + TCP 테스트 3개, 총 92개 통과 |
| Linux Docker, Python 3.14.7 | 위 92개 + 실제 PostgreSQL 인증 통합 테스트 5개, 총 97개 통과 |
| 정적 검사 | ruff 검사·포맷, mypy 앱 24개 파일, pip check 통과 |
| 배포 이미지 | 빌드 성공, 포함된 Alembic 파일로 SQL 생성 성공, 실제 liveness·OpenAPI 응답 확인, UID 10001 실행 |

실제 PostgreSQL 17.11에서 서로 다른 조직 2개와 사용자 3개를 만들었다. 정상 키의 소속 조회, 잘못된 키·폐기된 키 거부, 해시 저장, 인증 후 DB 트랜잭션 해제, 정상 시험 스트림, 기본 RAG 미준비 응답, 질문 바이트 제한, CLI 발급·폐기를 확인했다.

테스트 DB는 전용 Compose 프로젝트의 내부 네트워크와 임시 메모리 저장소를 사용한다. 호스트 포트는 열지 않는다. 비밀번호는 실행 시 생성하고 기록하지 않는다. 리뷰에서 관리 CLI 테스트가 일반 DB 환경변수를 따라갈 수 있는 문제를 발견했다. 일반 DB 주소를 닫힌 포트로 바꾸는 실패 테스트를 먼저 실행한 뒤, 하위 프로세스에 테스트 DB 주소를 명시적으로 넘겨 해결했다.

OpenAPI 생성 중 스트리밍 응답의 기본 상태 코드를 추론하지 못하는 오류도 테스트로 재현했다. 경로에 상태 코드와 요청·응답 스키마를 명시했고 Bearer 인증도 자동 문서에 표시한다.

## 남은 경계

이번 검증은 인증으로 소속을 결정하는 단계다. 실제 문서의 조직별 검색 제한·삭제 권한은 Task 6·9에서 검증한다. 이미 시작한 요청은 인증 시점의 Identity를 사용하며, 키 폐기가 기존 스트림을 강제로 종료하지는 않는다.

사용자별 속도 제한·전체 로그 보안·종료 처리는 Task 10에서 이어간다. DB를 사용하는 앱과 통합 테스트의 실행 기준은 Linux Docker다. Windows에서는 DB 없는 단위·TCP 테스트를 확인했다. Psycopg 비동기 연결은 Windows의 기본 Proactor 루프를 지원하지 않으므로, 관리 CLI와 마이그레이션은 Selector 루프를 명시한다. [Psycopg 공식 설명](https://www.psycopg.org/psycopg3/docs/advanced/async.html)

SQLAlchemy는 `postgresql+psycopg` 주소를 `create_async_engine()`과 함께 사용할 때 비동기 드라이버를 선택한다. [SQLAlchemy 공식 설명](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html#module-sqlalchemy.dialects.postgresql.psycopg)
