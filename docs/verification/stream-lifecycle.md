# 스트리밍 수명주기 검증

검증 날짜: 2026-09-10. Task 3의 범위다.

## 쉽게 설명하면

식당에 자리가 없으면 정해진 인원까지만 줄을 서고, 오래 기다리면 돌아가도록 했다. 손님이 떠나거나 음식을 받지 않으면 계속 만들지 않고 작업을 멈춘다. 사용한 자리를 정리한 뒤에 다음 손님을 받는다.

여기서 자리는 질문 처리 권한이고, 음식은 AI가 조금씩 보내는 답변이다. 실제 AI 모델 대신 시험용 서버로 이런 상황을 재현했다.

## 구현과 의사결정

- `Admission`은 실행 수·대기 수·대기 시간을 제한한다. 기다린 순서대로 권한을 주고, 취소·시간 초과 시 권한을 반환한다. 운영 계획은 실행 2개/대기 4개/대기 10초다.
- 하나의 이벤트 루프에서 상태 변경 중 `await`를 하지 않는다. 계획의 async lock 대신 이 방식을 사용해 취소가 반환 작업을 중단할 틈을 없앴다. 여러 프로세스에 걸친 전역 제한은 아니다.
- 처리 권한을 받은 뒤 준비 작업부터 스트리밍·연결 정리까지 기본 120초로 제한한다. 마지막 최대 1초를 정리용으로 남긴다. 한 번의 전송이 막히면 기본 10초 뒤 중단한다.
- 생성과 전송 사이에 별도 무한 큐를 두지 않는다. 앞의 데이터를 전송해야 다음 데이터를 읽는다. 이벤트는 최대 64 KiB다.
- 응답 시작 전 실패는 HTTP 오류, 시작 후 실패는 SSE `error`로 전달한다. `done` 이후 오류를 추가로 보내지 않는다. 끊어진 연결에는 전달을 보장할 수 없다.
- 자원 정리를 먼저 수행하고 오류 전송을 시도한다. 정리 작업을 별도로 소유해 정상 응답 직후 도착하는 연결 종료 신호도 정리를 취소하지 못하게 했다. 자원 종료 함수는 비동기 취소에 협조해야 한다.
- 스트림을 읽는 도중 발생한 HTTPX 예외도 안전한 오류로 변환한다. HTTP 연결을 여는 순간에만 예외를 변환하면 부족하다는 점을 실제 TCP 테스트에서 확인했다.

## 확인한 사례

| 범위 | 확인 내용 |
|---|---|
| 단위 테스트 | 실행·대기 상한, FIFO, 대기 만료·취소, 권한 인계 직후 취소 |
| ASGI 시험 | 정상 완료, 시작 전 실패, 전송 정체, 실행 제한, 요청 취소, 준비 중 연결 종료 |
| 회귀 테스트 | 오류 전송보다 먼저 정리, 중복 응답 방지, 내부 예외 비노출, 마지막 전송 직후 연결 종료 |
| 실제 TCP | 첫 답변 뒤 연결 종료, upstream 무응답, 수신하지 않는 클라이언트, 종료 후 처리 권한 재사용 |

읽지 않는 클라이언트 시험은 작은 소켓 버퍼에 큰 이벤트를 반복 전송한다. 실행 제한보다 먼저 생성이 멈추고 자원과 권한이 반환되는지 확인한다. 생성한 이벤트 수도 제한한다. 프로세스 메모리 사용량이나 GPU 처리량을 측정한 시험은 아니다.
