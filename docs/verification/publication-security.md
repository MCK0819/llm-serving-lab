# 게시 전 민감정보 확인

2026-09-17 코드와 GPU 배포 이미지의 게시 준비 검사다. 비밀정보는 화면에서 가리는 것만으로 충분하지 않다. Git 기록이나 이미지에 들어간 비밀값은 제거하고, 실제 자격 증명이었다면 폐기·재발급해야 한다.

## 확인 범위

- 게시할 HEAD의 전체 Git 기록을 로컬 bundle로 만들어 네트워크가 차단된 Gitleaks 컨테이너에서 검사했다. 보고서는 `--redact=100`으로 값을 가리고 Git에서 제외된 `.cache` 아래에 보관했다.
- 도구 이미지 digest: `ghcr.io/gitleaks/gitleaks@sha256:c00b6bd0aeb3071cbcb79009cb16a60dd9e0a7c60e2be9ab65d25e6bc8abbb7f`.
- 최초 검사에서 공개 Qwen tokenizer revision 한 건이 API 키로 오탐됐다. `.gitleaksignore`에는 해당 커밋·파일·줄·규칙의 fingerprint만 예외로 기록했다. 파일 전체나 API 키 탐지 규칙을 제외하지 않았다.
- Docker 이미지 설정과 전체 빌드 명령 기록을 검사했고 탐지 결과는 없었다.
- 추가 빌드 컨텍스트는 시작 도구와 SSH 설정으로 제한된다. 소스 저장소 전체, `.env`, 사용자 홈이나 자격 증명 파일을 복사하지 않는다. 빌드 시 SSH host key가 생성되지만 같은 RUN 단계에서 삭제되므로 추가 레이어에 보존하지 않는다. 인증키를 빌드 인자나 환경값으로 주입하지 않았다.
- 완성된 이미지에서 host key와 authorized_keys가 포함되지 않았음을 확인했다. 실제 키 인증·터널 시험은 일회용 컨테이너 내부에서 생성한 시험용 키만 사용했다. 실행 중 생긴 키를 이미지로 commit하지 않았다.

자동 검사에서 탐지되지 않았다는 결과는 모든 종류의 민감정보가 없음을 수학적으로 보장하지 않는다. 공개 기반 이미지의 모든 바이너리를 독립 감사한 결과도 아니다. 이 프로젝트에서 추가한 파일, Git 기록, 이미지 설정·빌드 내역과 SSH 키 보관 여부를 확인한 기록이다. 모델 이름·공개 revision·공개 이미지 digest는 인증 비밀이 아니므로 재현성을 위해 남긴다.

## 게시 상태

사용자는 민감정보 확인 후 푸시를 승인했다. 소스 브랜치 푸시와 GHCR 이미지 업로드는 별도 작업이다. 이미지 업로드에는 GHCR 쓰기 인증이 필요하며, 로그인 토큰은 채팅·명령 인자·Git 파일에 넣지 않는다. 이미지의 공개 설정 완료와 원격 pull 검증 전에는 게시 완료라고 기록하지 않는다.
