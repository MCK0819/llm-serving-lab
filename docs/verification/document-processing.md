# PDF를 검색용 데이터로 바꾸기

검증 기간: 2026-09-13~14. 대상: 구현 계획 7단계.

7단계의 목적은 맡긴 문서를 읽고, 필요한 부분을 찾을 수 있는 형태로 바꾸는 것이다. 예를 들어 “연차 휴가는 사전에 신청합니다”라는 문장을 PDF에서 꺼내고, 문서의 페이지 번호를 유지한 채 작은 조각으로 나눈다. 조각마다 의미를 비교할 때 사용할 숫자 384개를 만든다. 이를 임베딩이라고 한다.

이 과정은 답변 생성이나 새 모델 학습이 아니다. 실제 임베딩 계산은 별도의 CPU TEI 서버가 수행한다. Python 앱은 글자 추출·길이 계산·HTTP 통신을 담당하고 모델 가중치를 불러오지 않는다.

## 처리 규칙

- 텍스트 선택이 가능한 PDF만 대상으로 한다. 이미지 속 글자를 읽는 OCR은 포함하지 않는다.
- 암호화 PDF, 텍스트가 없는 PDF, 100페이지 또는 추출 문자 100만 자를 넘는 문서는 거절한다. 빈 페이지는 건너뛰되 실제 페이지 번호는 유지한다.
- 청크는 최대 300토큰, 같은 페이지 안에서 겹치는 부분은 최대 40토큰이다. 전체 청크는 5,000개까지다. 문단·문장 끝을 우선하며 내용 누락과 무한 반복을 검사한다.
- 저장할 본문은 그대로 두고 임베딩 요청 시 문서에는 `passage: `, 질문에는 `query: `를 붙인다. 본문에 이미 같은 말이 있어도 사용자 내용이므로 지우지 않는다.
- 접두어와 특수 토큰까지 포함해 E5 입력은 512토큰 이하여야 한다. 초과 부분을 몰래 잘라내지 않는다.
- 임베딩 요청은 최대 16개씩 보낸다. 384차원인지, 잘못된 숫자나 길이가 0인 벡터가 아닌지 확인한 후 크기를 정규화한다.
- 응답 본문은 최대 256 KiB, 한 배치의 전체 대기는 기본 30초다. 오류 응답 원문을 사용자에게 노출하지 않고, 취소·시간 초과 시 HTTP 연결을 닫는다.

## 도구 선택 이유

PDF 텍스트 추출에는 `pypdf`를 사용한다. 처음부터 OCR이나 별도 문서 처리 서비스를 추가하지 않고 읽을 수 있는 PDF에 집중하기 위해서다.

모델별 토큰 수는 `transformers`의 로컬 토크나이저로 계산한다. 같은 한글 문장도 E5와 Qwen이 나누는 방식이 다르므로 글자 수로 대신 계산하지 않는다. Qwen은 메시지를 감싸는 형식과 답변 시작 표시까지 계산한다. 이 용도로 PyTorch나 생성 모델 가중치는 설치·다운로드하지 않는다.

`scripts.cache_tokenizers`는 지정한 모델 버전의 토크나이저 파일만 내려받고 해시 기록을 만든다. 실제 처리 시에는 로컬 캐시만 읽는다. 다운로드 준비 단계와 테스트 실행을 구분해 네트워크 없이도 같은 파일로 재현하도록 했다.

## 검증과 한계

합성 PDF와 직접 작성한 한국어 PDF를 사용한다. 단위 테스트에는 실제 모델 서버를 요구하지 않고, 별도 통합 테스트에서 고정한 E5·Qwen 토크나이저와 CPU TEI를 사용한다. 통합 시험의 입력은 실제 사내 자료가 아니다.

- Windows 단위 테스트와 TCP 스트리밍 회귀 시험: **193개 통과**.
- Linux·실제 PostgreSQL 전체 시험: **236개 통과, 모델 환경 필요 시험 7개 제외**. 제외한 7개는 아래 실제 CPU 시험에서 별도로 모두 통과했다.
- 실제 캐시의 E5·Qwen 토크나이저와 CPU TEI 통합 시험: **7개 통과**.
- Ruff 검사·포맷, mypy 42개 소스, pip check 통과.
- Python 3.14.7 실행 이미지 재빌드와 외부 네트워크 없는 패키지 import 확인. 기존 의존성 버전을 유지하고 새 패키지와 필요한 의존성만 추가했다. PyTorch 미설치를 확인했다.
- 검증용 TEI·PostgreSQL 컨테이너와 네트워크 정리. 기존 모델 캐시는 다음 시험을 위해 유지했다.
- TEI는 고정한 CPU 이미지 digest와 기존 캐시로 offline 모드에서 기동했다. `/info`의 실제 버전은 1.9.3, E5 모델 revision은 `614241f622f53c4eeff9890bdc4f31cfecc418b3`, 입력 한도 512, 클라이언트 배치 한도 16이다.

모델 서버 통합 시험에는 작성한 한국어 PDF→청크→벡터, 모델 버전 일치, 벡터 384차원·유한성·정규화, 긴 입력의 서버 측 422 거절을 포함한다. 한 번의 연결 확인이며 속도나 검색 품질 벤치마크는 아니다. 생성 모델의 GPU 가중치는 실행하지 않았다.

실제 모델 파일로 검사하면서 모의 토크나이저 시험만으로는 찾지 못한 차이를 확인했다. Transformers 5.17의 Qwen 메시지 변환 결과는 `input_ids` 등을 담은 구조로 반환됐다. 구조의 항목 수를 토큰 수로 계산하면 입력 예산을 과소평가한다. 실제 `input_ids` 길이를 읽도록 보완하고 동일한 반환 형식의 회귀 테스트를 추가했다.

E5가 문장 끝의 제로폭 문자(U+200B·U+FEFF·U+200D)를 계산에서 생략하는 경우도 확인했다. 토큰 위치만 따라 자르면 남은 원문을 처리하지 못해 정상 문서를 거절했다. 원문 끝까지 포함할 수 있는지 토큰 예산을 다시 검사해 문자를 보존하도록 수정했다. 긴 문서는 남은 페이지 전체를 반복해서 토큰화하지 않고 현재 청크 주변만 계산하도록 제한했다.

작성한 PDF는 `.gitattributes`에서 바이너리로 지정했다. Windows와 Linux 사이의 줄바꿈 변환으로 PDF 내부 바이트 위치가 달라지는 것을 방지한다.

PDF 글자 수 제한은 압축 해제 중의 메모리 사용량까지 보장하지 않는다. 비정상 PDF의 메모리·실행 시간 제한은 8단계 Worker의 프로세스 실행 경계에서 함께 적용한다. 여러 열·표·복잡한 배치의 PDF에서 읽는 순서가 맞는지는 별도 품질 평가가 필요하다.

7단계는 처리 부품을 만드는 범위다. 업로드 작업을 실제로 집어 처리하고 재시작 후 이어받는 Worker는 8단계, 검색과 생성 답변 연결은 9단계다. 원격 GPU 서빙과 성능 벤치마크는 아직 완료하지 않았다.
