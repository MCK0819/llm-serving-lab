# 문서 근거를 연결하는 RAG

질문을 받으면 먼저 그 사람의 조직에서 읽을 수 있는 문서를 찾는다. 찾은 내용을 질문과 함께 생성 모델에 전달하고, 답변 앞에 어떤 문서의 몇 쪽을 참고했는지 보낸다. 이 흐름이 RAG다.

## 이번 단계의 동작

1. API Key로 사용자와 조직을 확인한다. 요청에서 조직·모델·출력 길이를 바꿀 수 없다.
2. 기존 동시 처리 제한 안에서 질문을 E5 임베딩으로 바꾼다. `query: ` 접두어를 포함해 512토큰을 넘으면 거절한다.
3. 같은 조직의 `ready` 문서 중 삭제되지 않고 임베딩 버전이 일치하는 청크만 검색한다. 이 조건을 적용한 뒤 가까운 다섯 개를 선택한다.
4. 시스템 지시·질문·문서·채팅 형식을 합친 실제 Qwen 입력 토큰 수를 센다. 기본 3,584토큰을 넘으면 검색 순위가 낮은 청크부터 제외한다. 하나도 넣을 수 없으면 422 오류를 반환한다.
5. 남긴 문서만 `S1`, `S2` 같은 출처 번호로 모델에 전달하고, 같은 출처 목록을 SSE 응답에 한 번 보낸다. 답변은 이어서 스트리밍한다.

검색 결과가 없으면 생성 모델을 호출하지 않고 “관련 문서에서 답변 근거를 찾지 못했습니다.”를 반환한다. 완료 이유는 `no_context`, 토큰 사용량은 null이다. 모델이 답했으면 `stop` 또는 `length`만 허용하며, 모델에서 받은 `no_context`는 정상 종료로 인정하지 않는다.

기존 `StreamResponse`가 처리 자리·시간 제한·연결 정리를 계속 소유한다. `RagService.prepare(identity, question, stack)`는 그 안에서 검색과 모델 연결을 준비한다. 계획에 있던 서비스가 응답 객체까지 만드는 형태를 그대로 추가하면 처리 자리를 두 번 확보할 수 있어, 검증된 기존 흐름에 연결했다.

문장 준비에 사용하는 CPU 작업은 별도로 기본 두 개까지 허용한다. 사용자가 끊어도 이미 실행 중인 Python 스레드를 강제로 멈출 수는 없다. 요청은 취소하되 CPU 작업이 실제 끝날 때만 이 제한의 자리를 반환한다. 자리가 없으면 추가 작업을 쌓지 않고 `503 prompt_busy`를 반환한다. 이 제한은 요청 전체의 기존 동시 처리 제한과 함께 적용한다.

## 권한·삭제·입력의 경계

다른 조직의 문서가 가장 유사해도 검색 후보에서 제외한다. 검색을 마치면 DB 연결을 반환하고 모델에 요청한다. 근거를 확보한 뒤 문서가 삭제되면 이미 진행 중인 답변은 기존 근거로 끝날 수 있지만, 이후 질문에는 그 문서가 들어가지 않는다.

문서 이름과 내용은 JSON 데이터로 전달하고 문서 안의 명령을 따르지 말라는 시스템 지시를 둔다. 이는 프롬프트 인젝션을 완전히 차단한다는 뜻이 아니다. 조직 격리는 DB 조건으로 강제하며, 모델에는 파일·도구 실행 권한을 주지 않는다.

검색은 정확한 코사인 거리 정렬이다. 최소 유사도 점수로 거절하는 기능은 아직 없으므로, 검색 결과가 있다는 사실만으로 질문에 충분한 근거가 있다고 보장하지 않는다. 한국어 답변 품질과 근거 충실도는 후속 평가에서 확인한다.

## 실행 준비

API 프로세스에 다음 설정이 필요하다. 두 토크나이저 경로는 함께 지정하고 DB도 설정한다. 로컬 캐시만 읽으며 시작 시 모델을 다운로드하지 않는다.

```text
LLM_LAB_RAG_EMBEDDING_TOKENIZER_PATH=<고정 E5 토크나이저 캐시 경로>
LLM_LAB_RAG_GENERATION_TOKENIZER_PATH=<고정 Qwen 토크나이저 캐시 경로>
LLM_LAB_EMBEDDING_URL=<API에서 접근 가능한 내부 TEI 주소>
LLM_LAB_INFERENCE_URL=<API에서 접근 가능한 내부 vLLM 주소>
```

경로를 지정하지 않으면 기존 문서 API는 사용할 수 있지만 질문은 `503 rag_unavailable`을 반환한다. 경로를 지정했는데 토크나이저를 읽을 수 없으면 API 시작을 실패시킨다. HTTP 연결은 앱 시작과 종료에 맞춰 관리하고, 질문마다 토크나이저를 다시 불러오지 않는다.

애플리케이션 Compose는 E5·Qwen 캐시를 읽기 전용으로 API에 연결한다. `LLM_LAB_INFERENCE_URL`은 실제 내부 vLLM 주소로 설정해야 한다. 기본 localhost 주소는 실제 GPU 서버 배포를 대신하지 않으며, 컨테이너의 localhost는 호스트 PC가 아니다. 공개 인터넷에 인증 없는 vLLM을 노출하지 않는다.

## 검증과 남은 범위

GPU 없이 실제 PostgreSQL·인증·검색·API·SSE를 연결하고 HTTP 시험 서버로 임베딩과 생성을 대체해 검증한다. 별도 시험에서는 캐시된 실제 Qwen 토크나이저로 전체 채팅 형식의 토큰 수와 출처 대응을 확인한다. 이 결과를 실제 GPU 답변이나 모델 품질 검증으로 표현하지 않는다.

요청 횟수 제한은 10단계에서 구현한다. 현재 동시 처리·대기열·입력 길이 제한은 있지만 사용자별 분당 횟수 제한이 완성된 상태는 아니다. 원격 GPU 실행·품질 평가·성능 측정도 별도 단계다.

2026-09-16 검증에서 실제 Qwen 토크나이저의 한국어 프롬프트 축소 시험을 통과했다. 로컬 단위 테스트는 227개 통과했고, 이후 추가된 시작 설정의 환경 분리 수정도 해당 테스트 3개로 재확인했다. 기존 TCP 스트리밍 시험 3개도 RAG 변경과 함께 통과했다. Ruff·포맷·mypy·의존성 검사는 통과했다.

코드 검토에서 요청 취소 뒤 CPU 작업이 계속 남는 문제를 발견했다. 제한된 작업 집합을 실제 작업 완료까지 유지하는 방식으로 수정하고, 연결 종료와 실행 시간 초과를 각각 시험했다. 이 검증은 GPU 성능 측정이 아니다.

최종 Linux/PostgreSQL 전체 시험은 **292개 통과, 10개 제외**였다(21.92초). 제외된 항목은 별도 모델 캐시·TEI 또는 Worker 프로세스 환경이 필요한 시험이며, 실제 Qwen 프롬프트 시험은 로컬 캐시를 지정한 별도 실행에서 통과했다. 운영 이미지 빌드와 이미지 안 RAG 모듈 로딩, 결합 Compose 설정 검사도 통과했다. 실제 TEI와 원격 vLLM을 연결한 운영 전체 실행은 이번 검증 범위가 아니다.
