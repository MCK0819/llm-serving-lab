# llm-serving-lab 문서

회사 문서를 올리면 AI가 그 문서에서 근거를 찾아 질문에 답하는 서비스입니다.

이 프로젝트를 만드는 진짜 목적은 **AI가 답하는 서비스를 직접 운영하는 방법을 배우고, 그 실력을 보여주는 것**입니다. 여러 사람이 한꺼번에 질문해도 감당할 수 있는지, 다른 회사의 문서가 섞이지 않는지, 문제가 생기면 어떻게 알아내고 해결할지를 확인합니다.

2026-09-09 대화에서 합의한 내용을 기록했습니다. 2026-09-10 설계 검토가 승인되어 단계별 구현 계획을 작성했습니다. 첫 API 구현과 로컬·Docker 실행 검증을 진행했습니다. [개발 안내](development.md)와 [검증 기록](verification/bootstrap.md)을 참고하세요. 초기 생성 모델은 Qwen3-4B-Instruct-2507, 임베딩 모델은 multilingual-e5-small로 정했습니다. 실제 실행·품질·성능은 검증 전입니다. 예산은 4주 최대 10만 원(목표 6~8만 원)으로 합의했습니다. 업체·GPU는 미선정이며 공개 요금 비교는 최종 견적이 아닙니다.

[API와 운영 규칙](superpowers/specs/2026-09-10-llm-serving-lab-contracts.md)의 초기 기본값도 승인되었습니다. [단계별 구현 계획](superpowers/plans/2026-09-10-llm-serving-lab.md)은 14개 작업의 파일·테스트·완료 기준을 정리합니다.

## 기록 원칙

현재 구현·검증 결과는 [문서 접수](verification/documents.md), [PDF 텍스트 추출·청크·CPU 임베딩](verification/document-processing.md), [Worker 중단 복구](verification/worker-recovery.md)에 기록한다. CPU 임베딩과 Worker 처리를 구현했으며, 원격 GPU 생성·RAG 연결은 아직 남아 있다.

- 쉬운 설명 → 구체적인 예 → 기술 용어 순서로 설명합니다. 약어는 처음 등장할 때 뜻을 풀어 씁니다.
- 비유는 이해를 돕는 용도입니다. 실제로 보장하는 동작과 한계는 별도로 적습니다.
- 각 선택에는 해결하려는 문제, 선택한 방법, 선택 이유, 감수할 단점을 적습니다.
- 설계 명세에는 현재 동작 계약을 유지합니다.
- 의사결정은 ADR 번호로 추적합니다. 방향이 변경되면 기존 이유를 삭제하지 않고 새 기록으로 대체 관계를 남깁니다.
- 제안과 합의를 구분합니다. 성능 예상치를 측정 결과로 기록하지 않습니다.
- 구현 중 확인된 제약, 실패한 실험, 개선 전후 수치는 재현 조건과 함께 별도로 기록합니다.

프로젝트 이름은 `llm-serving-lab`입니다. 현재 물리적 작업 폴더는 `ai-serving-backend`이며 폴더 이동은 수행하지 않았습니다.



Python 기준은 **3.14**(현재 확인한 패치 3.14.7)입니다. 별도 가상환경과 Linux 컨테이너에서 첫 API 의존성 설치·실행을 검증했습니다. Worker·LLM 모델 관련 패키지 검증은 해당 단계에서 수행합니다.
